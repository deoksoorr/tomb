# 사냥 끝판 1단계: 초월 레벨 + 번아웃 단계 (2026-11-15, 만든 그대로)

> 처음 초안(같은 날)에서 바뀐 것: 초월 곡선 15,000 × 1.07^t, 하루 초월 판 구간(적립), 번아웃 배율 1.35, 저주 단계(2·4·6·8·10), 단계 상한 10, 하루 도전 5번, 개척자, 주간 번아웃 랭킹은 2단계로 미룸.
> 숫자는 모두 `apps/web/lib/rpg/endgame.ts` 한 곳 (서버 검증·보상·화면·게임·안내서가 같이 쓴다).

## 배경
- 사냥 최고 레벨 50 (1→50 누적 EXP 약 17만). 오픈 1주 만에 50 달성자가 나왔다.
- 플레이어 다수가 게임 업계 7~10년차 이상 → 최적 루트를 바로 계산한다. **최대 효율로 해도 몇 달** 걸려야 한다.

## 원칙
1. 1~50 구간(EXP 곡선·능력치·기존 사냥터)은 그대로. `MAX_LEVEL` 50 그대로.
2. 끝판 보상은 포인트가 아니라 자랑거리(칭호·★ 표시·랭킹). 포인트는 기존 사냥 한도 그대로, 칭호 능력(등급 보너스)도 그대로.
3. Redis 명령 추가는 최소 (아래 "Redis 명령" 참고).
4. 서버 검증(판 결과 상한)은 기존 방식 유지 — 번아웃 배율·저주(제한 시간)를 상한 계산에 반영.

## A. 초월 레벨 (★51 ~ ★100)
- 레벨 50에서 얻는 EXP 중 **지옥 사냥터(번아웃 포함)** EXP만 초월 EXP(`tExp`)로 쌓인다. 초월 레벨 `tLevel` = 0..50 (표시 ★51..★100, 0 = 아직). 다른 난이도·미니게임 EXP는 예전처럼 버린다.
- 레벨 감소(levelPenalty)는 그대로: 레벨 50이면 분기 마감(Lv.42)·구조조정(Lv.48)은 100%, 회식 3차(Lv.30)·축제장(Lv.36)은 10%. **번아웃 단계는 감소 없음** (레벨 50 전용 콘텐츠라서 — 회식 3차 단계가 2%·10%가 되지 않게).
- 곡선: `tExpToNext(t) = round(15000 × 1.07^t)` (t → t+1). ★51 = 15,000, ★100 직전 = 412,949, 합계 6,097,935.
- 판 EXP → 초월 EXP 배율 `TRANSCEND_EXP_MUL = 0.049`. 11/15 실측 (시드 400개 평균, 레벨 50, 모든 몬스터·졸개·조각·정예까지 다 잡은 판):
  - 회식 3차 15,351 (×10% 감소) · 축제장 16,983 (×10%) · **분기 마감 23,837 · 구조조정 27,937** → 두 곳 평균 25,887 × 0.049 ≈ **1,268** (목표 1,275).
  - 매일 100% 20판만: 하루 약 2.5만 → ★100까지 약 240일. 매일 60판(100%·30%·10% 구간 끝까지): 하루 약 3.6만 → 약 170일. ★51은 첫날 12판 남짓.
- 능력: 초월 5레벨마다 능력치 1포인트 (`statPointsEarned(level, tLevel)`, STAT_MAX 그대로). 레벨이 오르는 그 저장(CAS) 안에서만 더하므로 두 번 받지 않는다. 능력치 초기화·레벨 맞추기도 초월 몫을 센다.
- 표시: 사냥 로비 위 줄(Lv.50 ★53 · 초월 EXP 막대) · 캐릭터 탭 · 결과 화면 · 레벨 랭킹(`Lv.50 ★53`, 아래 줄 초월 경험치).
- 레벨 랭킹 정렬 = 레벨 → 초월 레벨 → 초월 EXP. 점수 `레벨 × 1e9 + (레벨 50이면 tLevel × 1e7 + tExp, 아니면 경험치)` — 옛 기록(50, 0)은 그대로 맞물린다. 판 끝 기록 때 쓰는 그대로 (명령 추가 없음).

## B. 하루 초월 판 구간
- 레벨 50의 지옥 판(번아웃 포함)은 **시작하면** 초월 판 1판 (끝내지 않아도). 하루는 한국 시각 **새벽 5시**에 바뀐다 (`lib/gameDay`).
- 그날 index번째 판(0부터)의 구간: 앞 (20 + 적립) 판 100%, 다음 20판 30%, 다음 20판 10%, 그 뒤는 **연습 판** (초월 EXP 0, 드롭 없음, 포인트는 기존 사냥 한도 그대로).
- 적립: 그날 못 쓴 100% 판(20 + 적립 − 한 판)이 다음 날로 넘어가고, 통째로 쉰 날은 하루 20씩, 최대 40. 모두 0에서 시작 (처음 초월 판을 하는 날).
- 서버가 판 시작 때 구간을 정해 티켓(`tt`)에 싣는다 → 결과를 낼 때 화면 말을 믿지 않는다.
- 화면: 출발 탭 위 "오늘 초월 판 12/35 [100%] · 적립 15판" (칩 색: 초록 100% · 노랑 30% · 주황 10% · 회색 연습), 결과 화면에 받은 초월 EXP·구간 칩.

## C. 번아웃 단계 (1단계: 1 ~ 10)
- `BURNOUT_MAX_TIER = 10` (나중에 올린다). 레벨 50(테스트 서버 슈퍼 계정은 최대 레벨 취급)이면 출발 탭 사냥터 아래 [번아웃 단계] 상자: 단계 고르기(1..깬 단계 + 1), 배율·제한 시간·저주, 오늘 남은 도전.
- 해금: n단계를 **한 번도 쓰러지지 않고(died=false) 부활 쿠키도 안 먹고(p_cookie 0) 모든 웨이브·우두머리까지** 깨면 n+1단계가 열린다 (`bBest`). 깬 단계는 다시 해도 된다. 건너뛴 단계(슈퍼 계정)는 기록하지 않는다.
- 하루 도전 5번 (새벽 5시). 시작하면 도전 1번 + 초월 판 1판.
- 사냥터: 단계마다 [회식 3차, 축제장, 분기 마감, 구조조정] 차례 (`(n−1) % 4`). 그 사냥터의 지도·몬스터·기믹·우두머리 그대로.
- 몬스터: 체력·공격력 × 사냥터 power × **1.35^n**, 방어 × **1.12^n** (`monsterStats`의 scale — 새 패턴 없음). 10단계 체력 ×20.1.
- 저주 (누적, 엔진에 있는 값만 바꾼다):
  | 단계 | 이름 | 효과 |
  |---|---|---|
  | 2~ | 탕비실 절약 | 물약 회복 절반 |
  | 4~ | 탕비실 폐쇄 | 물약 금지 (부활 쿠키는 된다) |
  | 6~ | 연차 반려 | 받는 회복 절반 (스킬·재생·지형·흡혈) |
  | 8~ | 마감 당김 | 제한 시간 −20% (240 → 192초) |
  | 10~ | 사직서 즉시 수리 | 쓰러지면 그 자리에서 판 끝 (부활 쿠키 없음) |
  | 12~ | 독촉 메일 | 몬스터 이동 +20% (정의만, 상한 10이라 아직 안 나옴) |
  | 15~ | 연달아 회의 | 몬스터 공격 속도 +20% (정의만 — 엔진 연결은 상한을 올릴 때) |
  | 20~ | 마감 당김 Ⅱ | 제한 시간 −40% (−20% 대신, 정의만) |
- 보상: EXP = 지옥 EXP × (1 + 0.1 × 단계) → 초월 EXP (그날 구간 비율 적용). 포인트·드롭은 그 지옥 사냥터와 같다. 재료는 2단계에서.
- 주간 레이스: 번아웃 판은 늘 들어간다 (레벨 50에서 회식 3차·축제장은 보통 레이스 밖이지만 번아웃은 예외).

## D. 칭호
- 초월: ★60 「연봉 협상 대상자」(은) · ★75 「임원 후보」(금) · ★90 「상무님」(금) · ★100 「퇴사가 불가능한 자」(전설).
- 번아웃 첫 클리어: 5 「번아웃 생존자」(은) · 10 「야근이 일상」(금) · 20 「퇴근을 잊은 자」(금) · 30 「사무실이 집」(전설) — 20·30은 정의만 (상한 10).
- 개척자 「개척자」(금, 사냥 갈래): 끝판이 열린 뒤 **14일 안에** ★51에 닿거나 번아웃 1단계를 처음 깬 사람. 번호 #N = 닿은 차례 (저장소 INCR). 운영자(= 테스트 서버 슈퍼 계정) 제외 — 번호를 받지도 쓰지도 않는다. 칭호 카드에 "#N · 날짜 달성". 기간이 지나면 다시 얻을 수 없다.
  - 끝판이 열린 시각은 날짜를 박아 두지 않는다: 서버가 처음 필요할 때(레벨 50 캐릭터의 사냥 창·초월 판) 저장소에 SET NX로 한 번 적는다 → 운영·테스트 서버가 각자 14일.
- 칭호 id는 `@tomb/protocol` TITLE_IDS (`t_tlv60 … t_pioneer`). 진행 수치는 사냥 캐릭터에서 같이 읽는다 (tlv·burn·pioneer).

## 서버 검증
- 판 시작 티켓에 번아웃 단계(`bt`)·초월 구간(`tt`)을 싣는다. 시작 때: 레벨 50, 단계 ≤ 깬 단계 + 1(슈퍼 계정은 상한까지), 오늘 남은 도전, 지옥 사냥만 — 사냥터는 화면이 보낸 값이 아니라 단계로 정한다. 티켓 검증은 `bt`가 지옥·그 단계 사냥터와 맞는지도 본다.
- 결과 상한: 제한 시간(저주 반영)으로 티켓 만료·판정 시간(eff)을 자른다. 처치 속도·웨이브 시간 상한은 그대로 — 단계가 오르면 몬스터가 세져서 늦게 잡힐 뿐이라 정직한 판이 거절되지 않는다.
- 깔끔한 클리어 판정(해금)은 서버가 결과로 한다: 모든 웨이브 + died=false + p_cookie 안 씀.

## 저장 (캐릭터 JSON에 칸 추가 — 옛 저장값은 normalize가 0으로)
`tLevel, tExp, tDay, tRuns, tBank, bTries, bBest, pioneer?{n,at}`
- Redis 키 추가: `rpg:endgame:launch`(STRING, SET NX 한 번), `rpg:pioneer`(HASH 계정 → "번호|시각"), `rpg:pioneer:n`(INCR).

## Redis 명령
- 판 끝: 그대로 (초월·해금은 원래 캐릭터 저장 한 번에 얹는다, 레벨 랭킹도 원래 쓰던 그 한 번). 예외: 개척자 번호를 받는 그 한 판만 +3 (Lua 1 + 캐릭터 저장 2) — 계정마다 평생 한 번, 14일 안.
- 판 시작: 레벨 50 지옥 판만 +1 (그날 판 수·도전 수를 캐릭터에 저장 = CAS 2명령, 대신 응답의 캐릭터를 다시 읽지 않아 −1).
- 끝판이 열린 시각: 서버 인스턴스마다 처음 한 번 (Lua 1), 뒤로는 메모리.
- 칭호·랭킹: 추가 없음.

## 시험 (apps/web)
- `lib/rpg/endgame.test.ts`: 초월 곡선 숫자·합계, 레벨업·능력치(두 번 안 줌), 옛 저장값, 배율 실측 범위, 구간 경계, 적립 넘김·상한, 새벽 5시 경계, 사냥터 순환, 몬스터 배율, 저주 표, 제한 시간, 시작 검사, 해금 규칙(쓰러짐·부활 쿠키), 결과 검증(번아웃 EXP·줄어든 제한 시간), 개척자 기간, 칭호.
- `app/api/rpg/endgame.test.ts`: 레벨 50 아님·잠긴 단계·도전 소진 거절, 날짜 넘김, 초월 EXP·구간(연습 판 드롭 없음), 초월 능력치, 해금(쓰러짐·부활 쿠키), 개척자 번호(운영자 제외).
